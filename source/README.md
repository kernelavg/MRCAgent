# 🛰 MRC Agent

Десктоп-приложение для Windows: **100 агентов на Mercury 3** с минималистичным интерфейсом.
Агенты пишут код, ищут в интернете, работают в терминале, общаются друг с другом и **продолжают
работать после закрытия окна** — состояние живёт в SQLite, а не в окне.

```
┌──────────────────────────────────────────────────────────────────────┐
│  rail    список            чат / агенты / проект                     │
│  ──      ──────            ──────────────────────                    │
│  💬      Чаты           │  Mercury: ответ потоком, блоки кода         │
│  ✳       Агенты         │  100 карточек: кто что делает прямо сейчас │
│  📁      Проекты        │  клик по агенту → лента событий, сообщения  │
│  <>      Файлы          │  workspace: код, preview HTML, скачивание  │
│  ⚙       Настройки      │  профиль, пароль, ключ API, доступы, тема   │
└──────────────────────────────────────────────────────────────────────┘
```

## 1. Быстрый старт

### Вариант A — уже собранный `.exe` (Windows)

```
MRCAgent.exe
```

Первый запуск создаёт рядом папку `data\` (база и workspace) и открывает окно.
Python на компьютере получателя не нужен для собранного EXE. Для нативного окна нужен WebView2 Runtime; если он не обнаружен, приложение попробует открыть интерфейс в установленном браузере. Системные компоненты Windows, права доступа и политики безопасности тоже влияют на запуск. Размещайте EXE в папке пользователя с правом записи.

### Вариант B — из исходников

```bash
python app.py            # окно (нужен pywebview) или вкладка браузера
python app.py --no-open  # только фоновый сервер, UI откройте сами
python app.py --stop     # остановить фоновые рои
```

`app.py` поднимает **отдельный фоновый процесс** `server.py` и только потом открывает окно —
поэтому закрытие окна не убивает агентов.

Опционально: `pip install pywebview` — тогда вместо вкладки браузера будет нативное окно.

### Сборка `.exe` самому

Два пути:

| Что запустить | Когда |
|---|---|
| `build_mrcagent.bat` | рядом лежат исходники (папка проекта) → `dist\MRCAgent.exe` |
| `dist-share\MRCAgent-BUILD.bat` | **один файл для друга**: внутри уже упакован весь исходник (base64). Друг кладёт его в папку, двойной клик → рядом появляется `MRCAgent.exe` |

Если Python у друга нет, батник предложит поставить его через `winget` (или откроет python.org).
Иконка рисуется заново из `make_icon.py`, сборка — PyInstaller по `mrcagent.spec`
(один файл, без консоли, иконка `static/app.ico`). GitHub Actions workflow `.github/workflows/windows-build.yml` собирает Windows x64 EXE и проверяет фоновый сервер и файлы интерфейса.

## 2. Регистрация и вход

Своя, локальная, без внешних сервисов — **ник + пароль**:

```
[ Вход ] [ Регистрация ]     ← вкладки
никнейм  [ alex            ]
пароль   [ ••••••••    👁  ]
(регистрация) пароль ещё раз [ •••••••• ]
[  Войти  ] / [  Создать аккаунт  ]
```

Что важно знать:

| | |
|---|---|
| **Ник** | 2–32 символа, буквы/цифры/пробел/точка/дефис/`_`; уникален без учёта регистра |
| **Пароль** | минимум 6 символов; при регистрации вводится дважды |
| **Хранение** | только PBKDF2-HMAC-SHA256, 260 000 итераций + случайная соль, формат `pbkdf2_sha256$260000$соль$хэш` |
| **Сессия** | cookie `HttpOnly`, 30 дней — приложение не спрашивает пароль каждый раз |
| **Восстановление** | невозможно by design: нет почты и сервера, ключ только у вас. Пароль можно сменить, зная текущий: *Настройки → Пароль* |
| **Ник потом** | меняется в *Настройки → профиль*, проекты остаются на месте |

Аккаунты разные = базы разные: зашли под другим ником — свой чистый список проектов.
Всё лежит в `data/studio.db` на этом компьютере.

## 3. Ключ модели

По умолчанию приложение работает в **демо-режиме**: агенты имитируют активность
(поиск, код, терминал, сообщения), чтобы можно было посмотреть интерфейс без трат.

Чтобы агенты реально думали:

1. Ключ: https://platform.inceptionlabs.ai (новому — 100 млн токенов бесплатно)
2. *Настройки → Модель → API-ключ* → вставить → **Сохранить**
3. Выключить переключатель **Демо-режим**

Ключ хранится только локально в `data/studio.db`.

## 4. Что умеют агенты

| Роль | Сколько | Чем занимается |
|---|---|---|
| Планировщик | 1 | режет цель на файлы и порядок работ, его план уходит всем |
| **Главный** | 1 | в конце принимает работы всех, проверяет и сводит файлы в общий проект |
| Разведчик | 15 | `search` + `web`: ищет факты, открывает страницы, читает документацию |
| Архитектор | 10 | структура файлов, интерфейсы, данные |
| Программист | 33 | `write_file` — пишет реальные файлы в свой workspace |
| Тестировщик | 12 | `run` — запускает код в терминале, ищет падения |
| Ревьюер | 15 | находит дефекты по каждому файлу |
| Документатор | 13 | README и инструкции по факту |

### Как идёт работа

```
1. Планировщик   → план в projects.brief → он виден всем и попадает в промпты
2. Агенты        → работают параллельно, каждый в СВОЁМ workspace
                   (data/workspace/<проект>/agents/<агент>/), пишут, запускают, ломают — только у себя
3. Общение       → агенты переписываются (msg), по завершении каждый докладывает главному
4. Главный агент → принимает работы, проверяет ссылки и структуру,
                   сливает файлы из песочниц в общий workspace проекта,
                   собирает index.html из секций и пишет ОТЧЁТ-СБОРКИ.md
```

### Вложения

Кнопка «Прикрепить файл», drag & drop или `@` в поле цели — и файл уходит в проект.

```
вы:      Сделай из @тз.txt и @прайс.xlsx бота приёма заявок
файлы:   workspace/<проект>/files/тз.txt, files/прайс.xlsx
агенты:  видят список вложений в промпте, читают любой из них через attached("тз.txt")
```

Формат — любой: текст и код читаются как есть, `.docx/.xlsx/.pptx/.odt`, `.pdf` и архивы
разбираются без сторонних библиотек, картинки и бинарники принимаются и честно помечаются
«текст не извлекается». Файлов в одном запросе — сколько нужно; лимит размера — настройка
`max_upload_mb` (25 МБ, `0` — без лимита). Подробности — в разделе 10.

### Скиллы

Раздел «Скиллы» — свои правила для агентов в виде markdown:

```
# Стиль кода
- пиши короткими файлами
- комментарии по-русски
- в отчёте перечисли, что проверено
```

Включённые скиллы видит каждый агент роя; выключенный — не видит никто. Скилл можно
править, удалять, импортировать из `.md` и скачать обратно. Целиком агент читает его
инструментом `skill("Стиль кода")`. Подробности — в разделе 9.

**Личный workspace у каждого агента** — это главное отличие: тестировщик не сломает страницу,
которую пишет программист. В общий проект файлы попадают через главного агента: конфликт
решается по роли (код важнее остальных, при равенстве — более полный и более новый файл),
а проигравшие версии уходят в `_conflicts/<имя>/<ник-хэш>.<ext>`, чтобы ничего не потерять
и не держать мусор рядом с настоящим файлом.

> ⚠️ **Честно про «песочницу».** Песочница агента — это только рабочая папка, а не изоляция
> от системы. У агентов полный доступ к машине: терминал без фильтров, `cd` куда угодно,
> `rm` любого файла, обращение к любым адресам. Команда `run "echo x > ../../../../ESCAPED.txt"`
> действительно запишет файл за пределами workspace — так и задумано, ограничений мы не вводим.
> Если вы запускаете агентов на важной машине — делайте это в виртуалке, контейнере или на
> отдельном компьютере и держите бэкап: единственная настоящая граница здесь — сама система.

**Ники берутся из задачи.** Цель «Сделай крутой сайт про продукцию этой компании» → тема
«сайт про продукцию», и агенты называются «Ищущий информацию: сайт про продукцию»,
«Пишущий код: сайт про продукцию», «Главный проверяющий: сайт про продукцию».

**Лимитов на токены и действия нет.** Один ответ — до 8192 токенов (настраивается), количество
шагов агента не ограничено. Вместо лимитов — защита от зацикливания:

| Защита | Когда срабатывает | Что делает |
|---|---|---|
| повтор действия | одно и то же действие 3 раза подряд | останавливает агента, пишет причину в ленту |
| нет прогресса | 3 круга подряд файлы не менялись | останавливает агента: «нет прогресса» |
| время агента | 900 с на одного агента (настраивается) | мягко завершает и пишет причину |
| обрыв ответа | `finish_reason=length` | повтор с лимитом ×3, дальше — честная ошибка |

Инструменты (по одному на действие, модель просит их блоком):

```action
{"tool":"write_file","path":"src/app.py","content":"..."}
{"tool":"run","cmd":"python src/app.py"}
{"tool":"search","query":"aiogram 3 middleware"}
{"tool":"web","url":"https://docs.python.org/3/"}
{"tool":"read_shared","path":"index.html"}
{"tool":"msg","to_agent":"Kerix","text":"index.html готов, посмотри вёрстку"}
{"tool":"mail_search","query":"счёт","days":30,"unread":false,"limit":10}
{"tool":"mail_read","uid":42}
{"tool":"mail_send","to":"boss@example.org","subject":"Отчёт","body":"Готово, файлы во вложении"}
```

**Безопасность инструментов**

- файлы — только внутри `data/workspace/<проект>/` (никаких `../` и абсолютных путей);
- терминал — **любые команды** (пайпы, `&&`, редиректы, `cd` в любой каталог), таймаут на команду;
- сеть — только `http(s)`, включается/выключается в настройках;
- почта — читает и отправляет через YOUR ящик (IMAP/SMTP из настроек); отправку можно
  выключить отдельным тумблером, тогда агенты только читают и ищут;
- всё это можно выключить целиком: *Настройки → Доступы агентов*.

## 5. Интерфейс

- **Чаты** — потоковые ответы Mercury, markdown, блоки кода с кнопкой «копировать», история в базе.
- **Агенты** — сетка из 100 карточек. У каждого своя анимация активности: разведка (радар),
  чтение сайтов (глобус), генерация кода (курсор), правка файлов (карандаш), тесты (галочка),
  ревью (сканер), сообщения (пузырь). Работающие агенты подсвечены и «дышат».
- **Карточка агента** — вкладки «Сейчас», «Лента», «Сообщения», «Файлы»: что делает, кому что
  передал, какие файлы трогал, вывод терминала.
- **Проекты** — цель одной фразой → рой сам распределяет работы; прогресс и стоимость.
- **Файлы (workspace)** — дерево, редактор, сохранение, **preview HTML в iframe**, скачивание файла,
  копирование целиком.
- **Палитра команд** — `Ctrl/⌘ + K`: перейти куда угодно, запустить/остановить рой.
- **Настройки** — профиль и ник, ключ, модель, параллельность, доступы агентов, 5 акцентов, светлая тема.

## 6. Как это работает под капотом

```
app.py  ──запускает──►  server.py (фоновый демон, живёт без окна)
                          │
                          ├── SQLite  data/studio.db      пользователи, чаты, проекты,
                          │                               агенты, события, сообщения агентов
                          ├── orchestrator.py             пул из 100 агентов, статусы, инструменты
                          ├── tools.py                    файлы / терминал / сеть (с ограничениями)
                          ├── llm.py                      Mercury 3, SSE-стриминг, ретраи
                          ├── bus.py                      шина событий
                          └── SSE /api/stream  ────────►  браузер (UI обновляется в реальном времени)
```

- **Окно — это только клиент.** Закрыли окно — демон и рой работают дальше.
- **Открыли снова** — UI догоняет состояние из базы, `resume_all` продолжает прерванные проекты
  ровно с того места: уже готовые агенты повторно не работают и не тратят токены.
- **Жёсткий краш** — при следующем старте статусы `working` аккуратно переводятся в `idle`,
  проект встаёт на паузу и продолжается автоматически.
- **Планировщик идёт первым.** Его разбор цели сохраняется в `projects.brief`, показывается полосой
  над сеткой агентов и подмешивается в системный промпт остальным — рой действительно работает по плану,
  а не «каждый сам по себе».
- **Сообщения агентов доходят.** Адресат хранится по `id` агента (раньше писали ник, а искали по id —
  и получатель ничего не видел). Входящие подмешиваются в диалог агента на следующем шаге, в карточке
  видно «← от Umen» / «→ Corix».
- **Событийная модель** — каждое действие агента (мысль, файл, терминал, сообщение) пишется
  в `events` и одновременно летит в SSE. Потоковые `token`-события идут **только** в SSE:
  раньше они забивали базу десятками тысяч строк за прогон.
- **Переподключение без потерь.** Браузер присылает `Last-Event-ID`, сервер досылает пропущенные
  события из базы (с пометкой `replay`) — закрыли окно на середине, вернулись, лента целая.

### REST API (кратко)

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/bootstrap` | пользователь, настройки, проекты, чаты |
| POST | `/api/auth/register`, `/api/auth/login` | регистрация и вход |
| PUT | `/api/auth/password` | сменить пароль |
| PUT | `/api/profile` | сменить ник |
| GET/POST | `/api/chats`, `/api/chats/:id/messages` | чаты и потоковые ответы |
| GET/POST | `/api/projects` | список / создание проекта |
| POST | `/api/projects/:id/start|stop|pause|resume` | управление роем |
| GET | `/api/projects/:id/agents` | все агенты со статусами |
| GET | `/api/agents/:id` | агент + лента событий + сообщения |
| GET | `/api/agents/:id/console?since=<id>` | консоль агента: всё по порядку, с догрузкой (только владельцу) |
| GET | `/api/agents/:id/console.txt` | та же консоль файлом `.txt` |
| POST | `/api/mail/test` | проверить связь с почтой (IMAP) |
| GET | `/api/stream?project=<pid>` | SSE-поток событий; догоняет пропущенное по `Last-Event-ID` |
| GET/PUT | `/api/workspace/:pid/tree|file?agent=<aid>` | файлы: без `agent` — общий проект, с `agent` — песочница агента |
| GET | `/api/preview-token/:pid` → `/preview/<подпись>/:pid/:path`, `/download/...` | preview и скачивание только по подписанной ссылке (подпись выдаётся после входа, живёт 30 мин) |
| GET/PUT | `/api/settings` | настройки |
| POST | `/api/shutdown` | остановить демон (только с localhost) |

## 8. Если что-то не так

| Симптом | Решение |
|---|---|
| Окно не открылось, но агенты идут | UI: http://127.0.0.1:8777 · логи: `daemon.log` |
| «Порт занят» | `python app.py --stop` затем запуск снова (или `--port 8788`) |
| Забыл пароль | восстановить нельзя (нет сервера и почты). Ник виден в *Настройках*; новый ник = новый аккаунт |
| «Нет такого ника» | сначала вкладка «Регистрация», потом вход |
| Ответы не приходят | ключ + выключенный демо-режим; проверьте `base_url` (по умолчанию `api.inceptionlabs.ai/v1`) |
| Агенты «зависли» в работе | Стоп → Запустить; состояние в базе не теряется |
| Хочу чистую базу | закрыть приложение, удалить `data/studio.db`, открыть снова |
| Терминал не работает | *Настройки → Доступы агентов*: тумблер «Терминал» и выключенный «Строгий режим команд» |
| Команда висит и не снимается | теперь по таймауту убивается вся группа процессов команды (а не только shell) |
| «слишком много попыток входа» | считаем по IP, а не по нику: после 8 промахов ответ приходит с задержкой 1.5→3→6… до 30 с. Верный пароль пускает всегда — «выключить» вход владельцу ника посторонний не может |
| Windows: `python` открывает Microsoft Store | это заглушка магазина, а не Python. Поставьте с python.org и включите «Add python.exe to PATH»; сборочный `.bat` такие заглушки отсеивает сам |
| SmartScreen ругается на `.exe` | файл не подписан (сертификат подписи кода платный). Подпись — единственный способ убрать предупреждение, код её не заменяет |

## 9. Что нового в 1.5.0 — скиллы, музыка, обучение и никаких лимитов

| Пункт | Что сделано |
|---|---|
| **Скиллы агентов** | Новый раздел «Скиллы». Скилл — markdown-инструкция, которую видит **каждый** агент роя: стиль кода, тон ответов, что обязательно проверять. ## 16. Честные ограничения

- Агенты **не самообучаются** и не «думают в фоне» без вызова модели: активность = вызовы Mercury 3.
- Стоимость считается **по реальному usage модели** (вход/выход отдельно), а не «на глаз»:
  100 агентов × ответы ≈ **$0.01–0.03** за прогон (тариф Mercury 3 — $0.10/$0.35 за 1M токенов).
  В демо-режиме плашки показывают «демо» — там токены условные, и мы не выдаём их за деньги.
- Обрыв ответа по лимиту токенов больше не теряется молча: агент повторяет запрос с запасом,
  а если ответ снова обрезан — в ленте появляется ошибка и агент помечается сломанным, а не «готовым».
- Действия агента не ограничены количеством, но ограничены здравым смыслом: повтор действия,
  стояние без изменений в файлах и 900 секунд на агента — это стопы, а не лимиты на работу.
- Терминал — не ВМ: это обычные процессы от вашего пользователя (стартуют в папке проекта, но ничем не заперты).
  Агент технически может выполнить любую команду, которую можете вы — так и задумано по вашему запросу.
  Хотите поводок — включите «Строгий режим команд» в настройках.
- Модель не видит ваш экран и не читает файлы «сама»: всё, что она делает, идёт через
  инструменты агента — а они, повторимся, не ограничены папкой проекта.
- `.exe` собирается под Windows. На Linux/macOS работает то же самое через `python app.py`.

## MCP: внешние инструменты (1.6.0)

Откройте «Настройки → MCP — внешние инструменты». Введите имя и выберите
stdio (команда запуска локального MCP-сервера) либо HTTP (адрес Streamable
HTTP). При необходимости задайте переменные окружения или HTTP-заголовки.
Нажмите «Подключить», затем «Проверить»: так приложение получает список
инструментов и сохраняет его для промпта агентов. «Вызвать» позволяет
проверить отдельный инструмент с аргументами JSON. Для пробного сервера из
комплекта запустите приложение из каталога проекта и используйте команду
`python mcp_demo_server.py` (или путь к своему интерпретатору Python).

Агент обращается к инструменту блоком `action`, например:

```json
{"tool":"mcp","server":"Демо","name":"calc","args":{"expr":"2+3"}}
```

Таймаут 0 означает ожидание без программного ограничения времени. Секретные
HTTP-заголовки в списке не показываются; сервер MCP и его команда имеют
полномочия текущего пользователя системы, поэтому подключайте только
доверенные серверы. Удалённый сервер также получает переданные ему данные.
Автоматический повтор вызова инструмента отключён, чтобы не выполнять
потенциально изменяющие действия дважды.

Размеры файлов, текста, скиллов и отображаемого тела письма больше не
ограничены прежними жёсткими потолками по умолчанию. Фактический объём
ограничен памятью, диском и файловой системой. В проекте ещё остаются другие
ограничения, в том числе максимальное число одновременно работающих агентов,
параметры генерации модели, отдельные сокращённые превью и пользовательские
настройки ограничений. Внешние модели и серверы также имеют собственные лимиты.

### Живой ответ, Effort и черновик агента

Ответ в чате отображается по мере поступления фрагментов от API; если сам
провайдер отдаёт ответ одним фрагментом, приложение не может превратить его
в настоящий поток. В демо-режиме ответ выводится частями локально. Уровень
Effort можно выбрать прямо в шапке чата или в настройках модели — он
применяется к последующим запросам чата и агентов; значения зависят от модели.

Под ответом доступен сворачиваемый раздел «Рассуждение модели». Во вкладке
«Агенты» откройте карточку и выберите «Черновик»: там виден текущий вывод
агента и отдельный сворачиваемый блок рассуждения. Показывается только текст
рассуждения, явно переданный API в полях reasoning или reasoning_content;
скрытые внутренние мысли получить нельзя. Черновики и рассуждения не пишутся
в историю и исчезают при перезагрузке страницы; вывод может содержать личные
данные, поэтому показывайте экран только тем, кому доверяете.

### Плагины агентов

В боковой панели откройте **Плагины → Добавить плагин**. Поддерживается ZIP с типовой структурой плагина Claude Code: `.claude-plugin/plugin.json`, `skills/<имя>/SKILL.md`, `commands/*.md`, `.mcp.json`; также можно импортировать отдельный Markdown или JSON с `mcpServers`. Плагины добавляются выключенными. Перед включением раскройте и прочитайте инструкции, проверьте команды и адреса MCP, подтвердите включение. Инструкции добавляются в промпты агентов, связанные MCP-серверы включаются вместе с плагином и доступны через действующий инструмент `mcp`. В глобальных настройках MCP тоже должен быть включён. В разделе MCP можно проверить сервер и просмотреть его инструменты.

Импорт совместим только с перечисленным подмножеством формата: markdown-команды становятся инструкциями, а не slash-командами. Hooks, подагенты, LSP, внешние файлы и скрипты из архива, переменные `${CLAUDE_PLUGIN_ROOT}` и другие подстановки не исполняются и не импортируются; нестандартные пути из манифеста не обрабатываются. Пропущенные компоненты показываются в карточке. MCP, которому нужны эти возможности, настройте вручную через настройки MCP; это не полная совместимость с Claude Code или другими экосистемами. Инструкции сохраняются отдельными `.md` в каталоге данных `plugins/`, настройки — в базе. Удаление плагина удаляет и его инструкции, и связанные MCP-серверы. Отключение влияет на последующие обращения агентов; уже начатый вызов может завершиться.

Включайте только проверенные плагины: инструкции влияют на поведение агентов, а MCP может запускать локальные программы и обращаться к сети с правами пользователя, без песочницы. Импорт ZIP сам ничего не запускает; вызов или проверка MCP может запустить сервер.

### Обновление: агенты, копирование и MCP

- При ошибках агентов проект получает статус «завершён с ошибками», а не успешный статус. Кнопка «Повторить ошибки» запускает незавершённых агентов и повторно сводит результат; успешные рабочие агенты заново не запускаются. Расход токенов при повторном запуске суммируется.
- При HTTP 429 запросы одного роя согласованно ждут и повторяются с учётом Retry-After; отмена останавливает ожидание. Ограничения провайдера и число повторов остаются, успешная работа при исчерпанной квоте не гарантируется. Обрезанные ответы, сломанные действия и остановка защитой от зацикливания не считаются успешным завершением.
- Сообщения в чате и переписке агентов можно копировать кнопкой. На вкладке «Консоль» копируется полный доступный журнал агента; журнал может содержать чувствительные сведения, проверяйте его перед отправкой.
- MCP расположен в отдельном разделе с собственным сохранением настроек, списком серверов и импортом JSON. Импортированные из JSON серверы выключены до ручного включения. Серверы, поставленные через плагин, видны в разделе MCP и зависят от состояния своего плагина. Запускайте только доверенные серверы.
- Статус роя не означает, что продукт проверен или готов к публикации: код, объединённые файлы и работоспособность нужно проверять отдельно. Не все совместимые API предоставляют одинаковые заголовки ограничений и usage.

### Поток ответа в чате

Клиент запрашивает у модели потоковый ответ и показывает полученные части сразу по SSE; анимация не имитирует генерацию. Перед отправкой сообщения приложение дожидается подключения потока, а после перезагрузки страницы восстанавливает промежуточный ответ, пока сервер продолжает его получать. В демо-режиме выводится локальная заглушка. Скорость и момент первого фрагмента зависят от модели и провайдера; если провайдер буферизует ответ, приложение не может получить ещё не отправленные данные.

### Адреса LLM и проверка провайдера

В «Настройках» укажите Base URL, модель и API-ключ и нажмите «Проверить провайдера» до сохранения. Проверка отправляет короткий непотоковый запрос и может быть платной. Если поле ключа оставлено пустым, используется сохранённый ключ; для несохранённого адреса сохранённый ключ может использовать только администратор.

Клиент сначала пробует введённый адрес, затем при HTTP 404, 405, 410 или 501 дописывает `/chat/completions`; распознаются типичные формы потоковых и JSON-ответов. Это не гарантирует совместимость с каждым API: нестандартные протоколы, заголовки и форматы могут не поддерживаться. Расчёт стоимости по-прежнему основан на тарифе Mercury 3 и для остальных моделей является лишь приблизительной оценкой. Подробности и полный вывод тестов — в `docs/REPORT-ANY-URL.md`.
